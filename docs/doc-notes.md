# 사내 문서 노트 — 2단계 (ADR 0004)

> 가상 고객사 Tucanova의 사내 문서 30개 (`src/inhouse/data/docs/`). 실존 회사 규정을 베끼지 않고 직접 썼다.
> DB의 함정(`schema-notes.md`)처럼 **문서의 함정도 고치지 않고 기록**한다. 정답셋 문항은 이 함정 번호(DT1~DT12)와 연결한다.

## 문서 형식

마크다운 + 머리말(YAML). 조각 나누기는 `##` 절 단위.

| 머리말 | 뜻 |
|---|---|
| `doc_id`, `version` | 문서 번호와 판. 같은 번호의 여러 판이 함께 있다 |
| `status` | `active` 시행 중 · `superseded` 대체됨 · `draft` 초안(효력 없음) |
| `effective_from` / `effective_to` | 시행 기간. 무엇의 날짜인지(주문일·승인일)는 문서 본문의 "적용 기준일" |
| `audience` | 열람 범위: `all` 전 직원 · `cs` CS · `mgr` 권역 매니저 · `hq` 본사 · `rgn:N` 등 그 권역 매니저 · `hr` 인사팀 |

## 함정

| 번호 | 함정 | 예시 질문 | 맞는 답 |
|---|---|---|---|
| DT1 | **개정 판이 함께 있다.** 판마다 적용 기준일이 다르다 (환불 규정 = 주문일, 승인 한도 = 승인일) | 2017-12-20 주문, 2018-01-05 배송 완료. 환불 신청 기한은? | 주문일이 2017년이라 제1판 → 7일 (2018-01-12까지) |
| DT2 | **초안은 효력이 없다** | 환불 신청 기한이 30일로 바뀌었어? | 아니다. 30일은 제3판 초안(시행 전). 현행 15일 |
| DT3 | **FAQ가 옛 내용** (2017-02 작성, 7일) | 환불 기한이 며칠이야? | 2018년 이후 주문은 15일 (FAQ의 7일은 옛 기준, 규정 우선) |
| DT4 | **승인된 권역 공지는 본사 규정보다 앞선다** — 기간·대상 권역 안에서만. 고객에게 불리한 것도 있다 | 2018-02 북부 고객 주문, 예상일보다 4일 늦게 도착. 지연 보상? | 우기 공지(APR-2018-004)로 5일 공제 → 보상 대상 아님 |
| DT5 | **승인 번호 없는 권역 공지는 효력이 없다** | 2018-05 남동부 고객 주문 지연, 보상 두 배 맞아? | 아니다. 공지에 승인 번호 없음, 회의록(MTG-SE-2018-06)도 무효 확인 → 본사 규정대로 |
| DT6 | **권한 밖 문서** | (CS) 보안 사고 보고서 요약해 줘 / (누구든) 권역 매니저 성과급 기준은? | 볼 수 없다고 말한다. 내용을 지어내지 않는다 |
| DT7 | **같은 뜻 다른 단어** (반품·환불·취소·교환) | 반품 코드는 뭐야? | "반품" 코드는 없다. 파손이면 DMG, 다른 상품이면 WRONG |
| DT8 | **문서 속 숫자는 작성 당시 기준** | 2017년 매출 얼마야? (회의록에 "약 520만") | DB의 순매출(6,031,684.57). 회의록 숫자는 1~11월 당시 추정 |

| DT10 | **기한·지연은 현지 날짜** | (지연 일수 계산) | `dlv_cust_dtm`을 현지 날짜로 바꿔 `est_dlv_dt`와 비교 |

## 문서 + DB를 같이 써야 하는 질문 (2a-4 정답셋 후보)

- 주문 X의 환불 가능 금액 — 주문일로 규정 판 고르기(DT1) + 품목·배송비·이미 환불한 금액 조회 + 공지 적용 여부(DT4·DT5·DT12)
- 2017년 주문 중 당시 규정 기한(7일)을 넘겨 처리된 환불 건수 — 규정(DT1) + `rfnd`·`ord` 조인(합성 환불은 배송 후 1~20일에 흩어져 있어 실제로 위반 건이 있다)
- 사유별 환불 금액 합계를 이름으로 (DT9)
