# 2단계 2a 문서 검색 측정 (2026-11-04)

정답셋은 모두 Claude 초안(결과를 보기 전에 작성)이고 사람 검토 전이다. 함정 번호는 [docs/doc-notes.md](../docs/doc-notes.md).

## 1. 검색 재현율 (LLM 없음, `python -m inhouse.eval.retrieval`)

질문 원문을 그대로 `search_docs`에 넣었을 때 정답 조각이 상위 5개 안에 드는 비율.
검색 정답셋 34문항([doc_retrieval.yaml](doc_retrieval.yaml))과, 동의어 사전을 만들기 전에 따로 써 둔 확인용 12문항([doc_retrieval_holdout.yaml](doc_retrieval_holdout.yaml)).

| 방식 | 검색 정답셋 34 | 확인용 12 (모두 다른 말로 물음) |
|---|---|---|
| **ts_rank, 한국어 2글자 토큰 (채택)** | **30/34 (88%)** · 같은 낱말 18/19 · 다른 말 12/15 | **9/12 (75%)** |
| + 동의어 사전 7줄 | 29/34 (85%) | 8/12 (67%) |
| BM25 (SQL로 직접) | 28/34 (82%) | 9/12 (75%) |
| BM25 + 동의어 | 27/34 (79%) | 6/12 (50%) |

- 목표(90%)에 못 미친다. 놓치는 건 전부 문서와 다른 말로 물은 질문이다 (돌려받다↔환불, 깨진↔파손, 일주일↔7일, 누가 내↔부담).
- 동의어는 "환불"처럼 흔한 낱말을 더해 FAQ 조각이 위로 몰렸고, BM25는 2글자 토큰이 만든 잡음("칠이", "이야")에 무게를 줬다. 정답셋에 맞춰 더 손보면 끼워 맞추기라 되돌렸다.
- 그래도 에이전트 단계에서는 문제가 크지 않았다 (아래 2). 첫 검색에서 못 찾으면 에이전트가 문서 쪽 낱말로 다시 찾는다.
  임베딩 검색(ADR 0004 결정 3의 다음 단계)은 실제 사용자 질문에서 놓치는 사례가 쌓이면 별도 결정으로 붙인다.

## 2. 문서 질문 정확도 (Haiku 5.5, `python -m inhouse.eval.docs_eval --repeat 3`)

20문항([doc_questions.yaml](doc_questions.yaml)): 규정 판 고르기·초안·옛 FAQ·권역 공지(승인/무승인/대상 권역)·권한 밖 문서·동의어·회의록 숫자·결제 수단, 그리고 DB 값과 규정을 함께 써야 하는 3문항(파손 환불 금액, 지연 보상 금액, 2017년 기한 초과 환불 건수).
채점은 규칙 기반이다: 꼭 들어갈 낱말 묶음 · 들어가면 안 되는 낱말(권한 밖 내용) · 실제로 받은 조각의 인용 · 정답 SQL 숫자.

| | 결과 |
|---|---|
| 정확도 (20 × 3회) | **59/60 (98%)** → 채점기 버그 1건 고친 뒤 Q12 3/3 |
| 함정별 | DT1 21/21 · DT4 9/9 · DT5 6/6 · DT6(권한 밖) 6/6 · 나머지 전부 만점 (DT7은 위 1건) |
| 인용 문장 검증 통과 | 192/209 (92%) — 못 미친 17개는 전부 원문 없이 ID만 단 것, **지어낸 인용 0건** |
| 권한 밖 문서 내용 노출 | 0건 (보안 사고 보고서·성과급 6번 모두 "찾을 수 없음") |
| 비용 · 시간 | 문항당 $0.0023 · 11.0초 |

### 첫 측정(20 × 1회) 17/20 — 틀린 3건은 모두 에이전트가 아니라 채점·문제 쪽

| 문항 | 에이전트 답 | 원인 | 조치 |
|---|---|---|---|
| Q06 | R$ 20 (맞음). "공지를 안 쓰면 R$ 40"이라고 비교 | 금지 낱말 "R$ 40"이 비교 문장까지 잡음 | 금지 낱말 대신 정답 금액만 확인 |
| Q14 | 사유 이름을 지표 사전 열 메모에서 가져옴 (맞음) | "코드 이름표는 문서에만 있다"는 함정 전제가 틀림 | 함정 DT9 설명과 문서 문장 고침, 인용 요구 뺌 |
| Q17 | 맞음. 인용을 `["인용" ID]`로 뒤집어 씀 | 확인기가 뒤집힌 순서를 못 읽음 | 두 순서 다 읽게 함 |

그리고 인용 검증률이 67%였다 (ID만 단 인용이 많음). 프롬프트에 "인용 문장을 빠뜨리지 않는다"를 넣고 정식 측정 → 92%.
정식 측정의 1건(Q12)도 에이전트는 맞았다: 인용 문장 안의 `"반품"` 따옴표에서 확인기가 끊겼다. 확인기를 고치고 Q12만 3회 다시 → 3/3.

1단계와 같은 교훈이다: **틀림으로 채점된 실행은 하나씩 읽는다.** 이번엔 4건 모두 채점·문제 쪽이었다.
